## 项目计划书（V3 迭代版）

> **参赛赛题：** 第十九届全国大学生软件创新大赛 · 赛题二：随身AI互动导学
>
> **项目团队：** Concrete.AI
>
> **文档版本：** V3 迭代版 · 基于初赛版演进

## 版本演进说明

本版文档在保留初赛版"元智能体架构、自学习引擎、持久记忆、跨端协同"等核心技术资产的基础上，进行了**产品定位聚焦与场景深化**，核心变化如下：

1. **从"元智能体调度平台"回归"AI 学伴产品"**
   初赛版的叙事重心在"调度所有 AI 工具的元层智能体"。这个技术定位具备学术创新性，但容易被评委听成"又一个 Agent 平台"，与赛题"随身 AI 互动导学"的教育本质产生距离。V3 版将元智能体能力作为内核保留，但产品叙事回归到**大学生真实学习场景**——"陪你学、帮你做、越来越懂你"。

2. **从"通用任务执行"聚焦到"学做伴三位一体"**
   初赛版覆盖面过广（学习/科研/日程/通用效率），V3 版明确收缩为大学生最核心的两大需求——**学会知识** 和 **做完任务**，并新增"伴"维度，强调 AI 不是冰冷工具而是有温度的学习伙伴。

3. **从"重型底座全自研"转向"成熟技术 + 场景专精"**
   初赛版的 GRPO 强化学习、图数据库记忆、通用 GUI 自动化等重型技术承诺，在复赛阶段存在交付风险。V3 版将这些能力保留为技术演进方向，复赛阶段优先使用成熟方案（RAG/LLM API/WebSocket）夯实稳定可演示的核心闭环。

4. **从"代理执行"转向"Copilot 共做"**
   初赛版的交互范式偏向"用户下达指令 → Agent 自动执行 → 返回结果"。V3 版明确**不代做**——AI 和用户并肩推进，用户全程参与、全程知情，做完了用户也理解了整个过程。这既更符合教育场景，也直接回应了"AI 会不会让学生变懒"的质疑。

5. **新增"伴"的情感维度**
   AI 学伴不只是功能性工具。V3 版新增了主动回调、有温度的对话交互（气泡/表情/语气）、跨天连续记忆等设计，让系统具备"知心伙伴"的立体感。

> **核心原则：升级而非割裂。** 初赛版的技术深度是项目资产，V3 版是在此基础上的产品化聚焦。

## 一、项目概述

### 1.1 项目背景

#### 1.1.1 AI 工具泛滥时代下的"人类调度困境"

自 2022 年末 ChatGPT 问世以来，大语言模型驱动的 AI 工具经历了爆发式增长。截至 2025 年底，主流 AI 应用已覆盖代码生成（Claude Code、GitHub Copilot）、知识检索（Perplexity、NotebookLM）、多模态理解（Gemini、GPT-4o）、学术写作（Kimi、DeepSeek）等多个细分领域。然而，"百花齐放"的格局给用户带来了一个悖论性困境——**工具越多，调度越难**。

以一名计算机专业大学生完成课程项目为例：他需要用 Claude Code 生成代码骨架，切换到 ChatGPT 讨论算法细节，再转向 Gemini 检索文献，最后用 NotebookLM 整理笔记——每一次工具切换都意味着上下文断裂。**人类实际上承担了"AI 调度中枢"的角色**：拆解任务、分配工具、传递上下文、整合结果，这些本应由智能系统完成的工作反而成了用户负担。

更棘手的是，现有 AI 工具在犯错时表现出"固执"特性——在错误路径上越走越远，直到用户强制中断。这种"自信到底、一错再错"的行为模式，极大消耗了用户的时间和信任。

#### 1.1.2 大学生学习的两个核心痛点

尽管 AI 工具众多，大学生在学习中面临的核心困难可以归结为两类：

**"学不透"——知识获取碎片化、复习被动低效**

- 课程资料分散：PPT、录音、群文件、拍照笔记、老师口头补充彼此割裂
- 复习目标模糊：知道内容很多，但不知道先看什么、哪些是重点、自己哪里不会
- 碎片场景多：通勤、课间、排队时只能拿出手机，难以进入系统化复习状态
- 复习方式被动：总结很多、真正记住很少，缺少即时反馈与主动回忆

**"做不完"——任务链路长、协调成本高、容易拖延**

- 任务通常不是"不会"，而是不会拆、不会排、不会持续推进
- 学生容易被环境配置、数据整理、结果记录等杂事拖住
- 即便 AI 能生成内容，学生可能并没有真正理解过程
- 多门课并行时，最缺的不是答案，而是调度和协同

因此，本项目不把"学习"理解为单纯问答，而是定义为：

> **从理解知识，到完成任务，再到形成个人长期能力的连续闭环。**

#### 1.1.3 从单一智能体到元智能体的技术演进

<!-- 📢 文档用：以下内容体现技术深度和学术视野，不直接指导复赛开发 -->

学术界对 Agent 系统的研究正经历重要的范式转变。早期聚焦于打造更强的"单一智能体"，但随着场景复杂度提升，单一智能体的能力边界日益显现。这推动了多智能体协同和工具增强型智能体两大方向的兴起：

- **多智能体协作**：Mobile-Agent v3（Xu et al., 2025）采用 Manager-Executor-Reflector-Notetaker 四角色架构，在 AndroidWorld 基准上取得 73.3% 任务完成率，证明了多角色协作显著优于单 Agent 端到端执行。
- **技能库自进化**：SAGE 框架（Wang et al., 2025）引入强化学习驱动的自进化技能库，使 Agent 完成相似任务时交互步骤减少 26%，Token 消耗降低 59%。
- **持久记忆**：Mem0 系统（Chhikara et al., 2025）提出基于图结构的持久记忆架构，在 LOCOMO 基准上较 OpenAI 记忆方案取得 26% 的准确率提升。
- **示范学习**：LearnAct（Liu et al., 2025）证明仅需一次用户示范即可将 GUI 任务准确率从 19.3% 提升至 51.7%。

MetaAgent 的技术创新在于：**不做又一个 AI 工具，而是在更高抽象层级上编排和调度多种 AI 能力**，同时将这些能力包装为面向大学生的、有温度的学习伙伴产品。

#### 1.1.4 赛题契合度分析

赛题"随身 AI 互动导学"的关键词拆解：

| 关键词 | 赛题要求 | MetaAgent 如何契合 |
|--------|---------|-------------------|
| **随身** | 移动端轻量化操作 | 手机是主入口，随时拍/问/查/审批 |
| **AI** | 人工智能技术驱动 | RAG + LLM + 编排引擎 + 学习画像 |
| **互动** | 双向交互而非单向问答 | Copilot 共做 + 主动回调 + 进度聊天 |
| **导学** | 引导学习而非替代学习 | 不代做，和你一起做，全程你也在参与 |

### 1.2 产品定位

#### 一句话定位

> **MetaAgent 是一个以手机为主入口的 AI 学伴，围绕大学生"学会知识"和"做完任务"两大核心需求，通过 Copilot 共做、智能编排与长期记忆，在手机和电脑间协同帮用户把学习和任务推进到完成。**

#### 核心理念：陪你学，帮你做，越来越懂你

| 维度 | 关键词 | 说明 |
|------|--------|------|
| 📚 **学** | 学会 | 课程资料整理、RAG 精准问答、碎片复习、掌握度追踪 |
| 🔨 **做** | 做完 | 任务编排、Copilot 共做、跨端执行、产物交付 |
| 🤝 **伴** | 懂你 | 元学习、异步陪伴、主动感知、长期记忆、风格适配 |

#### 与现有产品的差异

| 对比维度 | NotebookLM | ChatGPT/Claude | Dify/OpenClaw | MetaAgent |
|---------|-----------|----------------|---------------|-----------|
| 产品本质 | 文档理解工具 | 通用对话引擎 | AI 开发平台 | **面向大学生的 AI 学伴** |
| 学习场景 | 围绕资料理解 | 通用问答 | 无 | **学做伴三位一体闭环** |
| 记忆能力 | 无跨会话记忆 | 有限上下文 | 无 | **持续积累学习画像** |
| 交互方向 | 单向 | 单向 | 单向 | **双向（AI 主动推送/回调）** |
| 任务能力 | 仅分析 | 仅对话 | 可编排但需开发 | **Copilot 共做 + 跨端执行** |
| 情感温度 | 工具感 | 工具感 | 开发平台 | **知心学伴、有温度** |

#### 我们不做什么

- 不做万能通用超级平台
- 不做面向开发者的 Agent 框架（那是 Dify 的定位）
- 不做完整桌面级 GUI 自动化平台
- 不做纯粹的拍题/答题/讲题应用
- 不做"把所有功能都塞进手机端"的全本地方案
- **不做代理——不替你学，不替你做**

## 二、核心设计

### 2.1 学做伴三位一体引擎

MetaAgent 的产品架构围绕"学做伴"三个维度展开，三者相互支撑形成飞轮：

```
         ┌──────────┐
         │  📚 学   │ ← 课程空间/RAG/碎片复习/掌握度
         │  学会知识 │
         └────┬─────┘
              │ 学习过程产出 → 记忆沉淀
              ▼
         ┌──────────┐
         │  🤝 伴   │ ← 元学习/异步陪伴/主动感知/连续记忆/风格适配
         │ 越来越懂你│
         └────┬─────┘
              │ 记忆驱动 → 更精准的编排和推荐
              ▼
         ┌──────────┐
         │  🔨 做   │ ← 编排树/Copilot共做/跨端执行/产物交付
         │  做完任务 │
         └────┬─────┘
              │ 任务完成过程 → 检验掌握/产出新资料
              └──────→ 回到"学"
```

**飞轮逻辑**：学习过程产生记忆 → 记忆让 AI 更懂你 → 更懂你则编排更精准、推荐更准确 → 做任务过程检验掌握度、产出新资料 → 新资料回到课程空间继续学习。

### 2.2 三大基础件

#### 基础件一：编排引擎（Plan Tree Engine）

**核心理念**：AI 事先规划一棵编排树，动态更新，用户可控。不是一步走完再想下一步，而是先有全局视野。

**与现有 Agent 的关键差异**：

| 现有 Agent（如 OpenClaw） | MetaAgent 编排引擎 |
|--------------------------|------------------|
| 一步一步执行，每步决定下一步 | **事先生成编排树**，全局规划 |
| 用户只能等着看结果 | **用户可审批/修改/砍分支/调优先级** |
| 出错了硬继续或直接放弃 | **谦虚机制：不确定就停下来问你** |
| 执行过程是黑箱 | **编排树可视化，进度实时同步** |

**编排树生命周期**：

```
用户输入目标
    ↓
任务理解 → 目标拆解 → 编排树生成（Plan Tree）
    ↓
展示给用户 → 用户审批/修改
    ↓
分阶段执行 → 持续汇报 → 可插话/变向
    ↓
动态重规划（如需）→ 继续执行
    ↓
产物交付 + 过程记录沉淀
```

**谦虚机制**：当 Agent 对某个决策的置信度低于阈值时，不硬做，而是主动征询用户。这解决了现有 Agent "自信到底、一错到底"的核心痛点。

<!-- 📢 文档用：可额外提及 Plan Tree 的动态重规划算法设计、与 LangGraph durable execution 的对比优势 -->

#### 基础件二：学习记忆引擎（Learning Profile Engine）

**核心理念**：被动积累，越用越懂你。聚焦学习相关信息，不做通用记忆平台。

**记忆三层架构**（复赛版）：

| 层级 | 记什么 | 怎么用 |
|------|--------|--------|
| **用户偏好层** | 输出风格、解释偏好（图示 vs 公式）、常用路径 | 个性化回答和产物格式 |
| **课程上下文层** | 在学哪些课、做过哪些实验、哪些概念标记为"模糊" | RAG 检索增强、复习推荐 |
| **近期会话层** | 最近的决策、已确认信息、未完成事项、中断位置 | 跨会话连续性、任务恢复 |

**记忆的核心体验是"连续感"**：

- 今天知道你昨天学了什么
- 记得你上周实验做到哪里中断了
- 知道你最近哪门课考试临近
- 理解你习惯什么样的解释方式

<!-- 📢 文档用：可引用 Mem0 的 Extraction-Update 管线（ADD/UPDATE/DELETE/NOOP）、图结构记忆增强层等学术背景，作为技术演进方向 -->

#### 基础件三：互动引擎（Copilot Interaction Engine）

**核心理念**：你是主驾,AI 是副驾。不代做，和你一起做。

**Copilot 共做范式**（与代理范式的区别）：

| 代理范式 | Copilot 共做范式 |
|---------|----------------|
| 用户下达指令 → AI 执行 → 返回结果 | 用户提出目标 → **一起规划** → **一起推进** → 一起完成 |
| 用户在等待中焦虑 | **用户全程参与、全程知道在干嘛** |
| 做完了用户可能不理解过程 | **做完了用户也理解了整个过程** |
| AI 犯错用户不知道 | **AI 不确定时主动问你** |

**双向对话机制**：

AI 不仅被动接收提问，还能主动发起对话：

- 复习提醒："你上周 TCP 三次握手还标记为'模糊'，要花 3 分钟复习一下吗？"
- 进度汇报："实验跑到 Epoch 15，accuracy 91.2%，要看看训练曲线吗？"
- 任务完成回调："测试跑完了，14/16 通过，要看详情吗？"
- 日程感知："今天下午有软体课，要我整理上次笔记吗？"

**Chat/Agent 双模式智能路由**：

简单问题 → Chat 模式秒回，不启动重量级流程
复杂任务 → Agent 模式，启动编排树 + 共做流程
模糊地带 → 询问用户偏好

**有温度的交互**：

AI 学伴不是冷冰冰的回答框。通过气泡样式、表情、语气设计，让交互有"朋友发消息"的感觉。这是"伴"的核心体感，也是与通用 AI 对话产品的体验差异。

## 三、功能设计

### 3.1 "学"模块功能

#### 功能一：课程空间

每门课程一个独立空间，承载该课程的所有上下文：

- 课件 PPT/PDF
- 课堂录音/转文字
- 手写笔记照片/OCR
- 整理后的笔记和知识卡片
- 老师强调的重点和作业要求
- 历次实验/作业产物

课程空间是 RAG 检索的上下文边界——当你问某门课的问题时，系统自动在对应课程空间中检索，而不是用通用知识泛泛回答。

#### 功能二：一键整理

用户将零散资料（PPT + 录音 + 板书照片）丢进课程空间，系统自动：

- 录音转文字 + 关键内容提取
- 图片 OCR + 内容归类
- 生成结构化笔记（含关键概念、例题、老师强调点）
- 生成 3~5 张知识卡片（可用于碎片复习）

#### 功能三：碎片复习

基于掌握度数据，在碎片时间推送个性化复习内容：

- 三档模式：5 分钟速刷 / 20 分钟系统复习 / 考前冲刺
- 内容形式：知识卡片 + 追问 + 错因定位
- 动态调整：答对的内容降低优先级，易错点反复强化
- 移动端优先：通知推送、锁屏卡片、碎片时段自动触发

#### 功能四：RAG 精准问答

不同于通用 LLM 的泛泛回答，MetaAgent 的问答基于：

- **课程空间 RAG**：直接引用你老师的 PPT 内容、课堂录音要点
- **学习画像**：知道你的知识水平，不会解释太浅或太深
- **关联上下文**：自动连接上周学的内容和这周新内容的关系

> 效果差异：你问"观察者模式怎么用"，通用 LLM 给你一篇通用介绍；MetaAgent 引用你老师 PPT 第 42 页的例子，结合你上周学的策略模式做对比，用你偏好的方式（图示 or 代码）解释。

### 3.2 "做"模块功能

#### 功能五：任务编排与 Copilot 共做

用户提出复杂任务（如"帮我完成 CNN 实验"），系统启动共做流程：

1. **理解**：分析目标，展示目标理解卡（目标/已知/未知/假设/预期产物）
2. **规划**：生成编排树（子任务/工具/时间/风险）
3. **审批**：用户可批准/修改/砍分支/调优先级
4. **执行**：分阶段推进，持续汇报进度
5. **协作**：用户可随时插话、改方向、补信息
6. **交付**：输出产物 + 过程摘要 + 可复习材料

#### 功能六：跨端执行

手机端发起任务、审批计划、查看进度、接收结果；
电脑端实际执行：代码运行、文件整理、文档生成、报告排版。

通信架构：
- 局域网 WebSocket 长连接（最稳定、最低延迟）
- 首次配对 Token 认证
- 断线重连 + 任务状态持久化

#### 功能七：异步双线程——后台干活 + 前台陪你

这是 MetaAgent 与传统 Agent 最关键的体验差异。传统 Agent 的模式是"你等着，它干完告诉你"；MetaAgent 的模式是**后台执行线程和前台对话线程并行运行**：

**后台线程**（执行面）：
- 电脑端按编排树分步执行任务
- 持续产出中间结果
- 在关键节点生成事件推送

**前台线程**（交互面，同时可用）：
- 你随时可以问它："现在跑到哪了？"
- 你可以让它讲解正在做的事："帮我解释一下这段代码在干嘛"
- 你可以吐槽/闲聊："这个实验好烦啊"，它还能鼓励你
- 你可以改变决策："先别跑完整实验了，把当前结果给我看看"
- 你可以发起新任务："顺便帮我查一下 batch normalization 的原理"

**异步双线程的核心体验**：

```
┌─ 后台执行线程 ──────────────────────────────────┐
│  [运行 train.py]  →  [收集日志]  →  [生成报告]   │
│       ↓ 事件推送        ↓ 事件推送                │
└───────┼─────────────────┼─────────────────────────┘
        ↓                 ↓
┌─ 前台对话线程 ──────────────────────────────────┐
│  用户："跑到哪了？"                               │
│  AI："Epoch 8/20, accuracy 87%, 预计还要 5 分钟"  │
│  用户："帮我讲讲 dropout 是干嘛的"                 │
│  AI："Dropout 是一种正则化技术，在你这个模型里…"   │
│  用户："算了，先停下来，把当前结果给我"             │
│  AI："好的，正在中止训练，生成阶段性报告…"          │
└─────────────────────────────────────────────────┘
```

**这意味着**：AI 帮你写实验报告的同时，你还能问它问题、让它解释原理、跟它讨论思路、甚至改变它的执行方向。它不是"丢出去就失联的外包"，而是**坐在你旁边一起干活的研友**——它手里在操作电脑，嘴上还能跟你聊。

### 3.3 "伴"模块功能——为什么它有 Meta 感

"伴"不是暧昧的陪伴，而是像一个**靠谱的研友/学习搭子**——了解你在学什么、记得你们上次聊到哪、帮你干活的时候还能跟你聊天。Meta 感来自以下五个具体维度：

| Meta 维度 | 具体做什么 | 为什么普通 AI 做不到 |
|-----------|-----------|-------------------|
| **元学习** | 从你的操作/偏好/纠正中学习，下次更合你意 | 普通 AI 每次从零开始，它越用越懂你 |
| **异步陪伴** | 后台干活的同时前台还能跟你聊、听你指挥 | 普通 Agent "丢出去就失联"，它一直在你身边 |
| **主动感知** | 知道你今天有什么课、什么截止、哪里卡住了 | 普通 AI 被动等你提问，它主动关心你 |
| **连续记忆** | 记得昨天聊到哪、上周做了什么、你哪里薄弱 | 普通 AI 每次重新认识你，它是老朋友 |
| **风格适配** | 知道你喜欢图示还是代码、简洁还是详细 | 普通 AI 千人一面，它专属于你 |

#### 功能八：学习画像与元学习

系统被动积累、持续更新用户画像，聚焦学习相关信息：

- 正在学哪些课程
- 最近做过哪些实验和作业
- 哪些概念总是混淆/标记为"模糊"
- 偏好图示解释还是公式推导
- 最近最容易拖延的是哪类任务
- 常用的工具和工作习惯

画像不只是静态记录，更是**元学习**的基础——系统从你的每次使用、每次纠正、每次偏好选择中学习，积累成对你越来越精准的理解。下次推荐复习路径、拆解任务、生成报告时，都会基于这份画像做出更合你意的决策。

<!-- 📢 文档用：可引用 LearnAct 的示范学习范式——从用户操作轨迹中提取可复用的 Skill，将"教一遍、会一次"作为元学习的技术背书 -->

#### 功能九：主动感知与推送

系统基于学习画像和任务状态，**主动发起对话**，而非被动等你提问，像一个时刻关注你进度的研友：

- 复习提醒："你上周 TCP 那块还标了问号，今天有 5 分钟可以过一下吗？"
- 任务催办："CNN 实验后天截止，你的代码还没跑完，要不要今晚一起把它搞定？"
- 结果回调："刚才那个模型跑完了，accuracy 94.2%！"
- 课程感知："今天下午有软体课，要我提前整理上次笔记吗？"
- 中断恢复："昨天 TCP 笔记整理到拥塞控制就中断了，要继续吗？"

#### 功能十：异步陪伴——它干活的时候你也不孤单

这是"伴"最核心的体感。当 AI 在后台帮你跑实验、写报告、整理资料时，**前台的它依然在**——你可以跟它聊天、问它问题、让它讲解、甚至吐槽。它不是一个"交出去就消失的外包"，而是一个坐在你旁边、手里在操作电脑、嘴上还能跟你聊的**学习搭子**。

（技术上这依赖于异步双线程架构，详见功能七。）

#### 功能十一：有温度的交互

- 气泡样式区分不同类型信息（提醒/汇报/协商/鼓励）
- 表情和轻松语气，像朋友发消息而非机器回复
- 陪伴感的微交互设计（问候/鼓励/阶段性成就，如"这周你已经复习了 3 门课，继续保持！"）

### 6.3 PC 端通用调度器（Orchestrator）

<!-- ✅ 实做 -->

**核心定位**：PC 端不是"只调 Claude 的转发器"，而是一个**通用调度器**。它自己决定每个子任务该交给谁——有的直接命令行最快，有的需要 Claude 写代码，有的需要浏览器操作，有的甚至可以去 Web 端 Gemini 发消息。

**架构参考**：借鉴 NanoClaw 的轻量单进程思想（MIT 协议），但场景和能力远超消息平台助手。

#### 整体结构

```text
MetaAgent PC Orchestrator（Python FastAPI）
  │
  ├── WebSocket Server ←→ Android App（双向实时通信）
  │
  ├── Plan Tree Engine（LangGraph 状态机）
  │     ├── 目标理解 → 编排树生成 → 审批门 → 分步执行 → 动态重规划
  │     ├── 谦虚机制：低置信度 → 暂停询问用户
  │     └── 中途变向：用户插话 → 修改编排树 → 继续执行
  │
  ├── Adapter Router（通用执行路由）
  │     ├── Claude Adapter     ← 代码编写/文件修改/复杂推理
  │     ├── Codex Adapter      ← 代码任务第二引擎（可选）
  │     ├── CLI Adapter        ← 命令行直接执行（最高效）
  │     ├── Browser Adapter    ← 浏览器 UI 操作/Web AI 交互
  │     ├── Local Runner       ← 跑实验/生成报告/画图
  │     └── Dify Adapter       ← 课程 RAG/工作流外挂（可选）
  │
  ├── Event Bus（异步事件总线）
  │     ├── 执行事件 → 广播给手机/WinUI3/记忆层/日志
  │     └── 三层事件：原始 → 结构化 → 用户可读
  │
  ├── Dialogue Loop（对话回路，与执行回路并行）
  │     └── 用户随时可问/插话/改方向/要求讲解
  │
  ├── Memory & Context
  │     ├── 学习画像读写
  │     ├── 课程空间 RAG 检索
  │     └── 会话上下文管理
  │
  └── State Store（SQLite）
        ├── TaskSession / PlanNode / Event
        └── 断点恢复 / 事件序号
```

#### Adapter 路由决策逻辑

```text
任务类型判断：
  简单命令（pip install / git pull / 跑脚本）  → CLI Adapter（最快）
  代码编写/修改/调试/重构                      → Claude Adapter
  代码任务第二引擎/并行代码任务                  → Codex Adapter
  文件整理/报告生成/实验画图                    → Local Runner
  网页操作/表单填写/信息抓取                    → Browser Adapter
  Web AI 交互（Gemini 网页版等）                → Browser Adapter
  课程资料问答/文档摘要                        → 本地 RAG 或 Dify Adapter
```

#### 编排树（Plan Tree）详细设计

<!-- ✅ 实做：用 LangGraph StateGraph 实现 -->

**为什么用 LangGraph**：LangGraph 天然提供状态机、条件分支、循环、中断恢复（durable execution）、人类审批（human-in-the-loop）——这些正是编排树最需要的能力，比自己从零写状态机快一个数量级。

**编排树节点数据结构**：

```json
{
  "id": "node_train",
  "title": "训练基础CNN模型",
  "kind": "exec | clarify | checkpoint | replan",
  "goal": "得到初步可用结果",
  "dependsOn": ["node_env_check"],
  "adapter": "claude | cli | local_runner | browser",
  "confidence": 0.81,
  "riskLevel": "low | medium | high",
  "requiresApproval": true,
  "rollback": "restore checkpoints",
  "explainToUser": "这一步会开始模型训练，预计耗时 5 分钟",
  "status": "pending | running | blocked | done | failed"
}
```

**编排树生命周期**：

| 阶段            | 说明                         | LangGraph 对应         |
| --------------- | ---------------------------- | ---------------------- |
| Draft Plan      | LLM 全局拆解，不执行         | 初始节点               |
| Negotiated Plan | 用户审批/砍分支/改优先级     | `interrupt` + 人工输入 |
| Executable Plan | 冻结部分节点，开始执行       | 状态转移               |
| Dynamic Replan  | 执行异常 → 动态修剪/插入节点 | 条件边 + 循环          |
| Postmortem      | 保存最终树/事件/产物         | 终态持久化             |

**谦虚机制触发条件**：

- 模型置信度 < 阈值
- 高风险动作（写文件/删文件/安装依赖/发外网请求）
- 信息缺口（缺数据路径/缺格式要求）
- 结果异常（训练结果离谱/测试失败）

<!-- 📢 文档用：可在技术报告中进一步阐述 Plan Tree 的形式化定义、与 LangGraph durable execution 的对比优势、动态重规划算法的时间复杂度分析 -->

#### 异步双回路（Dialogue Loop + Execution Loop）

<!-- ✅ 实做：Python asyncio 并发 -->

这是 MetaAgent 最核心的技术创新——**执行和对话并行运行**。

```text
TaskSession
 ├── DialogueLoop      # 对话回路（asyncio task）
 │    └── 接收用户消息 → 组织当前状态+事件为上下文 → LLM 生成回答
 │        不直接执行命令，只负责"陪聊+解释+收需求变更"
 │
 ├── ExecutionLoop     # 执行回路（asyncio task）
 │    └── 按 Plan Node 依次执行 → 调 Adapter → 产出原始事件
 │        不负责对话，只负责"干活+回报进度"
 │
 ├── EventBus          # 事件总线（连接两个回路）
 │    └── 执行事件广播给：手机 / WinUI3 / 对话回路 / 记忆层 / 日志
 │
 └── InterventionHandler  # 用户插话处理
      └── 用户说"先停下来" → pause ExecutionLoop → DialogueLoop 回答
          用户说"继续" → resume ExecutionLoop
          用户说"改方向" → 触发 replan → 修改编排树 → 继续
```

**事件三层分级**：

| 层级           | 给谁看    | 示例                                                         |
| -------------- | --------- | ------------------------------------------------------------ |
| 原始执行事件   | 日志/调试 | shell 输出、tool call、token stream                          |
| 结构化任务事件 | 业务逻辑  | `node.started`、`node.progress`、`approval.required`         |
| 用户可读事件   | 手机 UI   | "正在训练（8/20 轮，accuracy 87%）"、"需要你确认：是否覆盖 report.md" |

### 6.5 手机 ↔ PC 通信协议

<!-- ✅ 实做 -->

#### 协议选型

局域网优先的 **WebSocket 长连接** + **typed JSON 帧**（借鉴 OpenClaw Gateway 的 WS 控制面思想）。

#### 帧格式

**连接帧**：

```json
{ "type": "connect", "deviceId": "phone_xxx", "role": "mobile",
  "auth": { "token": "..." }, "capabilities": ["chat", "plan.approve", "task.observe"] }
```

**请求帧**：

```json
{ "type": "req", "id": "r_101", "method": "task.create",
  "params": { "goal": "帮我推进CNN实验", "courseId": "ml_01" } }
```

**事件帧**（服务端主动推送）：

```json
{ "type": "event", "event": "task.progress", "seq": 152, "taskId": "task_7788",
  "payload": { "planNodeId": "node_train", "status": "running",
               "message": "Epoch 8/20, accuracy 87.2%" } }
```

**插话帧**（用户中途干预）：

```json
{ "type": "req", "method": "task.intervene",
  "params": { "taskId": "task_7788", "mode": "pause_and_explain",
              "message": "为什么 accuracy 卡在 87 附近？" } }
```

#### 可靠性机制

| 机制               | 说明                                    |
| ------------------ | --------------------------------------- |
| 心跳               | 定时 ping/pong，断线自动重连            |
| 事件序号 `seq`     | 重连后从 `lastSeq` 补拉漏掉事件         |
| 快照 `snapshot`    | 连接上先给当前任务快照，再追增量事件    |
| 幂等键 `requestId` | 所有有副作用操作带 idempotency key      |
| 本地缓存           | Android Room 缓存最近任务快照，离线可看 |

### 6.6 学习记忆管线

<!-- ✅ 实做：复赛阶段用轻量三层架构 -->

**复用 Operit 已有能力**：`MemoryRepository` + ObjectBox + ONNX Embedding（paraphrase-multilingual-MiniLM-L12-v2, 384 维）+ HNSW 向量索引。

**三层记忆架构**：

| 层级         | 记什么                           | 存储                 | 怎么用                 |
| ------------ | -------------------------------- | -------------------- | ---------------------- |
| 用户偏好层   | 输出风格、解释偏好、常用路径     | SQLite KV            | 个性化回答和产物格式   |
| 课程上下文层 | 在学课程、做过的实验、"模糊"标记 | ObjectBox + 向量索引 | RAG 增强、复习推荐     |
| 近期会话层   | 最近决策、未完成事项、中断位置   | SQLite               | 跨会话连续性、任务恢复 |

**记忆抽取管线**：每次对话后异步触发 →

1. 对话内容 + 上下文 → LLM 抽取学习相关信息
2. 新信息与已有记忆比对 → 新增/更新/删除/跳过
3. 学习画像持续迭代

### 6.7 RAG + 学习画像的协同效应

这是 MetaAgent 相比通用 LLM 的核心优势：

```
通用 LLM = 世界知识 → 泛泛回答
MetaAgent = 世界知识 + 你的课件（RAG） + 你的画像（记忆） → 精准、个性化、有上下文的回答
```

**技术实现**：

- 课件资料导入 → 切块 → ONNX Embedding 向量化 → 课程空间索引
- 提问时组装上下文：`系统 prompt + 课程 RAG 命中 + 学习画像摘要 + 近期会话上下文`
- 回答引用来源标注（引用了哪份课件的哪一页）

### 7.1 核心用户画像

### 7.2 详细场景故事

#### 场景：课间快速捕获 + 自动整理

> 早上 10:05，软件体系结构课间。
> 
> 你掏出手机，对着黑板上的 UML 类图拍了一张，又录了 15 秒老师总结观察者模式要点。打开 MetaAgent，选择「软件体系结构」课程空间，点"导入"——照片和录音自动归档。

> 中午 12:30，你打开 App，看到系统已经整理好了：
> - 结构化笔记：观察者模式的定义、四个角色、适用场景、Java 实现示例

> - 3 张知识卡片，可以用于碎片复习
> - 系统还问："要不要生成今晚的复习路线？"

#### 场景：实验 Copilot 共做

> 晚上 8:00，宿舍里。
> 
> 你对 MetaAgent 说："帮我完成 CNN 实验的剩余部分，但不要直接替我写完。实验指导书在课程空间里。"
> 
> 系统识别为共做任务，编排树生成：
> ① 读取实验指导书 → ② 检查代码环境 → ③ 讨论实现思路 → ④ 运行训练 → ⑤ 分析结果 → ⑥ 生成报告
> 
> 你批准计划。电脑端开始训练，手机端实时看进度。
> 
> Epoch 10 时系统问你："验证集 accuracy 在 85% 附近波动，训练曲线看起来可能需要调 learning rate，要不要试试 0.001？"
> 
> 你说："试试。" 系统调整参数继续。
> 
> 跑完后你得到：训练曲线图 + 结果分析 + 实验报告草稿。
> **全程你知道在干什么，关键决策是你做的。**

#### 场景：异步长任务 + 回调

> 下午 2:00，图书馆。
> 
> 你说："帮我把课程项目代码跑一遍测试，整理日志。" 然后继续看数学。
> 
> 20 分钟后手机推送（带个小笑脸表情）："✅ 测试跑完啦～14/16 通过，7 和 12 失败了。要看详情还是先过？"
> 
> 你说："先把通过的整理成报告，失败的晚上回去看。"
> 系统继续。

#### 场景：跨天记忆连续

> 第二天早上打开 App。
> 
> MetaAgent："早上好！昨天 CNN 实验的报告我帮你整理好了。对了，你今天下午有计算机网络课，上次 TCP 拥塞控制那里你还标了问号，要花 2 分钟过一下吗？"

| 状态持久化 | `state_store/*`（SQLite） |
| RAG + 记忆层 | `rag/*`、`memory/*` |
| WebSocket 服务端 | `ws_server/*` |

### 开发启动前必须先定的 3 件事

> ⚠️ 四个人并行开发最怕的不是累，是**边界不清**。以下三件事必须在写第一行业务代码之前定死。

#### 1. 通信协议先定

字段统一，否则 Android 和 PC 会一直扯皮：

```
taskId / sessionId / requestId / event seq / nodeId / event type / payload schema
```

（详见 6.5 节帧格式定义）

#### 2. 任务状态机先定

至少统一这些状态，否则 UI 展示和后端逻辑对不上：

```
draft → planned → awaiting_approval → running → paused → waiting_user → done / failed / cancelled
```

#### 3. PlanNode 结构先定

编排树是核心创新，不先定 node schema 后面全乱：

```json
{
  "id": "string",
  "title": "string",
  "kind": "exec | clarify | checkpoint | replan",
  "status": "pending | running | blocked | done | failed",
  "dependsOn": ["nodeId"],
  "confidence": 0.0-1.0,
  "requiresApproval": true/false,
  "adapter": "claude | cli | local_runner | browser",
  "summary": "string"
}
```

## 十、总结

MetaAgent 的价值不在于做了一个"更强的 AI"，而在于重新定义了 AI 和大学生之间的关系：

- **不是替你学** → 而是 **陪你学**，让你用碎片时间高效复习，用 RAG 精准回答你的课程问题
- **不是替你做** → 而是 **帮你做**，和你一起规划、一起推进、你全程参与
- **不是冷冰冰的工具** → 而是 **越来越懂你的学伴**，记得你在学什么、做过什么、哪里不会

因此，MetaAgent 可以概括为：

> **一个懂你、陪你、和你一起把学习和任务推进到完成的 AI 学伴。**
